# Аналіз конкурентності та GIL

## 1. Вплив GIL на потоки

GIL (Global Interpreter Lock) — механізм CPython, який обмежує одночасне виконання Python-коду кількома потоками в межах одного інтерпретатора.

У проведеному експерименті використання чотирьох потоків зі звичайним Python забезпечило прискорення у 1.143 раза. При використанні восьми потоків продуктивність знизилася.

Невелике прискорення може пояснюватися паралельним читанням файлів, оскільки індексація включає як обчислення, так і операції введення-виведення.

## 2. Використання процесів

Окремі процеси мають власні інтерпретатори Python, тому можуть виконувати обчислення паралельно незалежно від GIL.

Однак створення процесів, передавання даних та об'єднання результатів потребують додаткових ресурсів.

У проведеному експерименті найкращий результат процесної індексації зі звичайним Python становив 0.319027 с, тоді як послідовна індексація тривала 0.102506 с.

Для корпусу із 300 документів використання процесів виявилося недоцільним.

## 3. Закон Амдала

Закон Амдала визначає обмеження прискорення програми при паралельному виконанні.

Формула:

S(N) = 1 / ((1 − P) + P / N),

де:

- S(N) — коефіцієнт прискорення;
- P — частка програми, яку можна виконувати паралельно;
- N — кількість воркерів.

У розробленій програмі обробка документів виконується паралельно, а об'єднання часткових індексів — послідовно.

Для чотирьох потоків без GIL час об'єднання становив 0.000637 с при загальному часі виконання 0.073769 с.

Частка часу об'єднання:

0.000637 / 0.073769 × 100% ≈ 0.86%.

Об'єднання індексів є лише однією з послідовних операцій. На загальну продуктивність також впливають читання файлів, розподіл завдань та керування воркерами.

## 4. Стан гонитви (Race Condition)

Стан гонитви виникає, коли результат виконання залежить від порядку одночасного доступу потоків до спільних даних.

При одночасному оновленні спільного лічильника або індексу можуть виникати проблеми узгодженості даних.

Для уникнення цього кожен воркер формує власний частковий індекс. Ідентифікатори документів розподіляються заздалегідь, а результати об'єднуються після завершення роботи воркерів.

Таким чином, воркери не змінюють спільний індекс під час паралельного виконання. Втрату оновлень у проведених експериментах не зафіксовано.

## 5. Python без GIL

Для експерименту використано Python 3.13.18 free-threaded. Відсутність активного GIL перевірено за допомогою sys._is_gil_enabled().

Результати потокової індексації:

| Потоки | З GIL | Без GIL |
|---:|---:|---:|
| 1 | 0.835 | 0.898 |
| 2 | 1.020 | 1.429 |
| 4 | 1.143 | 1.832 |
| 8 | 0.633 | 1.481 |

Найкращий результат отримано при використанні чотирьох потоків без GIL. Подальше збільшення кількості потоків не забезпечило додаткового прискорення.

Оскільки використовувалися різні версії Python, отриману різницю не можна пояснювати виключно відсутністю GIL.

## Висновок

Потокова індексація без GIL показала найкращу продуктивність на використаному корпусі. Використання окремих процесів не забезпечило прискорення через додаткові витрати паралельного виконання.
